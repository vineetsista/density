# DECISIONS

One line of rationale per choice the spec left open. Newest at the bottom.

1. Repo root is the invocation directory `~/projects/density` itself, not a nested `density/` folder: the spec's layout prefix names the repo, and nesting would break `pip install -e .` from the clone root.
2. The superpowers skill pack is not installed in this environment, so its skills cannot be invoked by name; the workflow is followed in substance instead: spec treated as interview output, plans written to docs/superpowers/plans/, subagent-driven implementation, TDD, and measured verification before any phase is called done.
3. `git init` was run first because the spec requires conventional commits and the directory was not a repository.
4. `uv` was not present on the machine; installed via the official standalone installer to ~/.local/bin.
5. Build backend is hatchling with a lazy, cached, import-time compile for the accel kernels instead of scikit-build-core as the wheel backend: scikit-build-core forces CMake onto every plain `pip install -e .` and cannot express an optional extension, which would break the zero-toolchain demo session. `pip install -e .[accel]` still works exactly as specced: the extra installs pybind11, the first import compiles the kernels with the system compiler, and any failure falls back silently to numpy with `density.ACCEL_ACTIVE` set accordingly.
6. COLD tier recall is defined and measured with rerank against the WARM int8 vectors (or HOT fp32 when present), and COLD footprint counts only the PQ or binary payload plus codebooks plus compressed traces: this is the only reading under which the spec's own footprint table (PQ 1/16x, binary 1/32x, both <= 0.08x) is arithmetically consistent with rerank.
7. All vectors are L2-normalized at ingest so cosine similarity equals dot product everywhere; documented in the embedding engine and the report methodology.
8. The PQ 16x-including-codebook gate is measured at m=128 for dim 768 (24x codes-only, comfortably over 16x after codebook overhead at 100k vectors); the API default stays m=dim/4, which is exactly 16x codes-only but dips just under 16x once the codebook is amortized over corpora smaller than about 1M vectors.
9. Accel parity in tests is measured as max abs diff scaled by the result magnitude (floor 1.0) rather than per-element ratio: scores that legitimately cancel toward zero would make raw ratios meaningless while the contract intent (1e-5 agreement) is preserved.
10. synth: default n_vectors = max(5000, int(gb * 100000)); the byte target is met by budgeting embeddings first and streaming conversations that only ever undershoot (by at most a few hundred bytes). Model names in the corpus are fictional (sable-large-2, sable-mini-1, kestrel-8b) to keep it vendor-neutral.
11. recall: verify_tiers grew a reranker_factory keyword beyond the contracted reranker argument. A Reranker needs the post-split leave-out database vectors, which only verify_tiers knows, so callers can pass a factory instead of a prebuilt instance. Resolution order when rerank depth is positive: explicit reranker, then reranker_factory(X_db), then ExactReranker(X_db) as the honest fallback. 00-contracts.md updated to match.
12. ingest: trace file discovery matches .jsonl plus numeric shard suffixes only (regex jsonl(.N)), not the contract's literal *.jsonl.*: silently decompressing a .jsonl.gz would break byte-exact replay. IngestStats gained observe() and merge() (additive counters; files can double-count across overlapping sets, pinned by tests). Unparseable ts or token values stay in extra with the field defaulting, so no input byte is lost.
13. shred: canonical reconstruction serializes events in a value-derived field order (a tool layout and a non-tool layout) instead of persisting a per-line key permutation; lines that do not match either layout fall to the residual store and the audit reports the residual rate honestly. Ref columns are variable-size list of int64 because pyarrow 25 cannot round-trip nullable fixed-size lists. Byte-identical content and extra payloads are sha256-interned to one stored copy, which is the dedup contract's own storage rule.
14. shred block stores use 16 MB concatenated zstd frames with no trained dictionary: measured on the synth corpus, a trained dictionary never repays its own bytes inside concatenated frames (dictionaries help small independent frames). zdict.train_dict stays implemented and tested for callers that compress small independent items; BlockReader random access by ref is unaffected.
15. store: one put_traces and one put_embeddings call per tier in v1 (a second raises StoreError suggesting a single batched call): incremental re-encode is deferred until the audit can re-verify recall after appends. put_traces(tier="hot") is rejected rather than pretending a raw passthrough bundle exists.
16. store: codec state persists as per-array .npy files plus a state.json map instead of .npz, because the zip container embeds timestamps and would break deterministic manifest checksums. Cross-tier rerank applies only when both tiers stored the identical id sequence; reranker preference is warm sq8, then hot fp32, then a one-time warning naming the unapplied recall floor.
17. density.audit collides with the density/audit/ package: importing any submodule rebinds the attribute to the module and shadows the function. The package module is made callable (ModuleType subclass forwarding to runner.run_audit), so both spec requirements hold under any import order.
18. store review fixes: PQ.search widens its rerank depth to at least k (mirroring binary), so k above the default depth cannot crash. Dataset trace counters track distinct resolved source paths, so the same corpus stored in two tiers is counted once. Store read paths wrap codec and zstd corruption into StoreError, and Store.verify() runs manifest sha256 verification on demand rather than on every open (hashing every file on open would tax large stores). replay refuses a trace_id whose lines differ across tiers instead of silently truncating. matryoshka_dims is exposed on put_embeddings per the contract, off by default. Lone-surrogate trace ids stay addressable only by their escaped form, documented in the store docstring.
19. synth realism redesign: the trace stream is a global time-ordered k-way merge over concurrent session lanes (lane count scales with corpus bytes; at 1 GB the median same-conversation gap is about 16 MiB, past zstd-19's 8 MiB window), system prompts are per-conversation compositions (shared persona base plus injected session context, resent byte-identically on every call), and message content is template plus slots from wide seeded spaces. Embeddings are a low-rank manifold mixture (rank 10 to 14, tau 0.60 to 0.75, iso 0.12, 35 percent near-duplicate groups): the previous isotropic full-rank mixture concentrated same-cluster distances into near-ties below quantization noise, which is both unrealistic (intrinsic dimension of modern sentence encoders is roughly 10 to 40) and degenerate for recall metrics.
20. bench harness: the pq-with-rerank config uses m=128 wherever 128 divides the dim (full dims 384 and 768) and d/2 in quick mode, with the actual m recorded in the JSON; COLD recall reranks through SQ8 on the leave-out database, matching DECISIONS item 6. The trace section embeds a small deliberate vector stub so the synth byte budget measures trace compression, and the corpus is cached under a parameter-stamped directory.
21. service: every error is structured {"error": {type, message}}; StoreError maps to 404 only for the two stable not-found message prefixes, otherwise 500; framework validation errors are remapped from 422 to 400; audit reports land next to the corpus path, never inside it.
22. shred refs store item indices, not (block, offset, length) triples: the store index already records every item length, so a ref is a pure function of append position; one int64 per row (byte-stream-split or delta packed) replaced three, cutting structured.parquet from 7.28 to 5.39 MB at 1 GB. Ref semantics (resolve to exact bytes) unchanged.
23. content and extra stores pack unique payloads similarity-sorted (whitespace-collapsed 64 byte template key, then raw 96 byte prefix, then sha256, then uid; spill-and-sort with bounded memory); frames are 64 MB with window_log 26 plus long-distance matching, parameters recorded in index.json and capped at window_log 27 so stock zstd always decompresses. Measured 37 percent off the content store; a single 206 MB frame and level 22 each bought under 1 percent and were rejected.
24. Full-scan replay materializes packed stores once to an anonymous temp file (SpilledItems): access order is unrelated to packed order, so per-item frame decompression would approach quadratic cost; the spill costs one sequential pass and disk equal to the store's uncompressed bytes.
25. BlockWriter caps in-flight uncompressed seals at 4: zstd-19 compresses slower than packing produces, and the cap bounds peak RAM at about (cap + 1) times the frame size regardless of corpus size.
